## 🔭 Depth — ml-infra / on-device ML / agent-systems

*What's the trend and what sparks curiosity.*

**ml-infra & on-device ML**: The front page is heavy with inference-tier releases (Flash models, "Ultrafast" branding) suggesting the competition has shifted from capability to speed and cost. On-device interest persists quietly — the Hillock neuro-symbolic memory engine running under 1.2GB VRAM is exactly the kind of constrained-hardware project that signals real edge deployment thinking.

- [Hillock – Local neuro-symbolic memory engine running in <1.2GB VRAM](https://news.ycombinator.com/item?id=49289158) — 14pts — neuro-symbolic hybrids running on consumer GPU memory are rare; the VRAM budget constraint is a serious engineering claim worth verifying

**agent-systems**: Coding agents are clearly mainstream now — Codex in ChatGPT desktop for Linux, a dedicated Launch HN for a faster coding agent, and multiple Show HNs building agent memory and observability. The meta-question HN is asking: who verifies the agent's work?

- [Launch HN: Bullet (YC S26) – A Faster Coding Agent](https://news.ycombinator.com/item?id=49283063) — 77pts — speed is the differentiator claim; in a market of coding agents, "faster" is a testable, concrete wedge worth watching

**Deep dives**:
- [Single log line is 49KB+ (ext4) / 110KB+ (btrfs) of systemd-journald disk writes](https://news.ycombinator.com/item?id=49290215) — 133pts 82c — if you run any Linux server with journald, this is a concrete I/O surprise; the btrfs number especially warrants attention before your next storage budget review
